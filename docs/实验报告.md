# 对照实验报告：规则、字段记忆、LLM 兜底各自的贡献

计划书第 8 节第 4 条、阶段 6 验收项。2026-10-12，代码版本见各节。

## 结论

1. **规则是主力。** 适配后的 4 个真实网申页面（Moka、北森、Wecruit、飞书招聘）共 78 个该填的字段，规则认对 78 个，认错 0、不该填却认出 0。在这些页面上，字段记忆和 LLM 都没有可补的空间。
2. **没见过的页面上，主要的损失不是“没认出”，而是“认错”和“没发现控件”。** 用适配前的规则去跑 Wecruit 和飞书（相当于两个没见过的网站）：41 个字段认对 27 个（66%），另有 7 个认错、1 个不该填的被填、4 个控件根本没被发现。字段记忆和 LLM 兜底只能处理“发现了控件但没认出”的那一类，这里只有 3 个。
3. **字段记忆和 LLM 兜底在这批数据上的上限相同：** 都只能补回那 3 个，把 27/41 提到 30/41（73%）。区别是记忆零风险、零调用，LLM 每页要一次调用（约 1,000–1,300 token），而且发出去的字段里大多数本来就该留空（适配后的 4 个页面上发出 30 个字段，全部该留空；适配前的 Wecruit 发出 17 个，14 个该留空），认出来就是填错。
4. **所以优先级是：规则（含真实快照回归）> 字段记忆 > LLM 兜底。** 这和计划书风险表里“LLM 兜底没提升就如实写，聚焦规则与记忆”的预案一致。LLM 兜底保留为用户点击才触发、结果一律标黄、本地再核对的辅助功能。
5. **LLM 的实际准确率还没测**：需要真实的 API Key（见文末“怎么复现”）。上面第 3 条是上限分析，不是实测。

## 方法

**数据**：`tests/fixtures/forms/real/` 下 4 份真实网申页面快照（已去敏），每个控件人工标注了正确答案（`data-expect`：应填的档案项，或 `none` 表示不该填）。档案用测试档案 `tests/fixtures/profile.ts`。

**统计口径**（`tests/fixtures/score.ts`）：

- 认对：认成了标注的档案项（包括第几段经历）。
- 认错：认成了别的档案项（最危险，会填错）。
- 漏认：没认出，或者控件根本没被发现。
- 不该填却认出：标注为 `none` 的字段被认成了档案项。

**三组**（`tests/experiment/ablation.exp.ts`）：

| 组 | 做法 |
|---|---|
| A 规则 | 只用词典规则，第一次打开页面 |
| B 规则 + 字段记忆 | 模拟用户第一次在候选卡里把漏认的字段逐个选对并勾“记住”，第二次打开同一网站时的识别结果 |
| C 规则 + LLM | 把规则没认出的字段（只有字段名、分区、选项）发给 LLM，结果经本地核对后计入；第二次打开时从记忆里认，不再调用 |

**“没见过的网站”怎么模拟**：Moka 和北森的规则是对着这两份快照调的，在它们上面测会高估。Wecruit 和飞书的快照是后来才拿到的（提交 15c986b 才适配），所以用适配前的代码（提交 4d3840d）跑这两份快照，当作“插件第一次遇到的网站”。

## 结果

### 1. 适配后（当前代码，提交 b4d6ade）

| 页面 | 控件数 | A 规则 | 认错 | 不该填却认出 | B 加记忆 | 发给 LLM 的字段 | 其中有正确答案的 |
|---|---|---|---|---|---|---|---|
| Moka · 达能 | 42 | 23/23 | 0 | 0 | 23/23 | 10 | 0 |
| 北森 · 转转 | 16 | 14/14 | 0 | 0 | 14/14 | 1 | 0 |
| Wecruit · 华润电力 | 61 | 32/32 | 0 | 0 | 32/32 | 15 | 0 |
| 飞书招聘 · 沐瞳科技 | 17 | 9/9 | 0 | 0 | 9/9 | 4 | 0 |
| **合计** | 136 | **78/78** | 0 | 0 | 78/78 | 30 | 0 |

发给 LLM 的 30 个字段都是档案里没有的（第二、三意向城市、英文名、国籍、有无亲属在本公司、论文发表、自我评价……），正确做法是留空。

### 2. 没见过的网站（适配前的代码，提交 4d3840d）

| 页面 | A 规则 | 认错 | 不该填却认出 | 漏认（其中控件没被发现） | B 加记忆 | C 加 LLM（上限） |
|---|---|---|---|---|---|---|
| Wecruit · 华润电力 | 22/32 | 7 | 1 | 3（0） | 25/32 | 25/32 |
| 飞书招聘 · 沐瞳科技 | 5/9 | 0 | 0 | 4（4） | 5/9 | 5/9 |
| **合计** | **27/41（66%）** | 7 | 1 | 7（4） | **30/41（73%）** | 30/41 |
| 适配后（对照） | 41/41 | 0 | 0 | 0 | | |

失分明细：

- Wecruit 认错 7 个：基本信息里的毕业院校、学历把教育经历的编号顶到了第 2 段（4 个）；“生源地（高考户籍地）”认成户口（2 个）；家属分区的“姓名”认成本人姓名（1 个）。另有“是否第一学历”这道是非题被当成学历（不该填却认出）。
- Wecruit 漏认 3 个：家属的“亲属关系”“工作单位”“职务或岗位”。这 3 个是记忆和 LLM 唯一能补的。
- 飞书漏认 4 个：渠道、学历、学历类型、成绩排名，都是改了类名前缀的 Ant Design 3 组件（下拉框、单选组），控件没被发现，记忆和 LLM 都看不到它们。

认错的 7 个字段已经填上了值，候选卡不会弹（只给空着的字段弹），字段记忆也就记不到；LLM 兜底只看没认出的字段，同样看不到。这类错误只能靠规则修，靠真实快照的回归测试防止再犯。

### 3. LLM 调用的成本

| | 适配后 4 个页面 | 适配前的 Wecruit |
|---|---|---|
| 每页调用次数（第一次打开，用户点了「让 AI 认一认」） | 1 | 1 |
| 每页发送字符数 | 2,440–2,943 | 2,996 |
| 估算 token（中文字符 × 0.6 + 其他 × 0.3，按 DeepSeek 文档的估算方法） | 1,005–1,268 | 1,295 |
| 第二次打开同一网站 | 0（按网站记住，直接认，仍标黄） | 0 |

发送的内容里大头是“档案项目录”（73 项），字段本身不多。北森只发了 1 个字段，仍有约 1,000 token。如果以后要省 token，可以只发和字段所在分区相关的目录。

## 安全上的结论

- 规则组在 4 个适配后的页面上认错 0、不该填却认出 0。
- LLM 组面对的大多是“本该留空”的字段，所以这个功能的主要风险是填错而不是漏填。现有的三道防线：只在用户点击时调用；本地核对（路径必须存在、分区对得上、下拉框不会是姓名电话）；写入一律标黄让用户核对。
- 字段记忆只记录用户亲自选的值，第二次打开时零调用、零新增风险。

## 局限

- 只有 4 个网站，“没见过的网站”只有 2 个，结论是方向性的，不是统计显著的。
- 字段记忆组假设用户第一次把漏认的字段都在候选卡里选对了。
- LLM 组还没用真实模型跑，第 2 节表里的 C 列是上限（假设 LLM 把能补的都补对，且不填错任何本该留空的字段）。
- 标注为 `none` 的字段里有少数是取舍问题（比如“第二意向城市”档案里只有一个意向城市字符串，按规则不拆开填），换一种标注口径数字会略有变化。
- 计划书第 8 节第 5 条“手填 vs 插件填 + 核对的耗时”需要真人计时，不在本报告里，方法见下。

## 怎么复现

```bash
npm run experiment                     # 当前代码，结果写到 docs/experiment/results.json
# 适配前的代码：
git worktree add /tmp/before-v9 4d3840d
# 把 tests/experiment/、tests/fixtures/（score.ts、profile.ts、forms/real/）、
# src/lib/ai/skills/fieldMatch.ts、vitest.experiment.config.ts 复制过去，再在那里运行
EXP_OUT=docs/experiment/old.json npx vitest run --config vitest.experiment.config.ts
```

**用真实 LLM 跑 C 组**：设置兼容 OpenAI 协议的接口，再运行同一个命令：

```bash
EXP_AI_BASE=https://api.deepseek.com/v1 EXP_AI_KEY=你的 Key EXP_AI_MODEL=deepseek-chat npm run experiment
```

结果里的 `llm.firstVisit` 是第一次打开、用了 LLM 之后的识别结果（认错、不该填却认出也会统计），`llm.revisit` 是第二次打开、从记忆里认的结果，`llm.tokens` 是服务商返回的实际 token 数。只发字段名、分区、选项和档案项目录，不发档案内容。

**耗时对比（待做，需要真人）**：选 2–3 个真实网申页面，同一个人各填两遍（先后顺序交替，避免第二遍更熟）。一遍完全手填，一遍点插件填写后逐项核对、补完没填的。从打开表单到所有必填项填完计时，不点提交。记录每页字段数、两种方式的用时、插件填错后改掉的个数。
