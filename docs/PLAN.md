## 1. 项目概述

**一句话**：用户在国内校招/社招网申页面点一下插件，插件把本地档案里的信息填进表单，并清楚告诉用户哪些填了、哪些没把握、哪些没填及原因；用户检查后**自己提交**。

**目标用户**：中国大陆应届生/求职者，秋招春招一次投几十家，反复填写相同信息。

**项目目标（两个）**
1. 做一个自己真能用的网申工具。
2. 作为简历项目（AI 应用开发方向）公开到 GitHub，要有可量化的数字和清晰的工程取舍可讲。

**差异化定位**：“能在真实网申页面上验证”的网申助手。现有开源项目多数只在自制模拟页上测试，北森、飞书招聘、大易支持弱。本项目建立真实页面快照回归集，公开各系统识别率与填写成功率，并用实验量化“规则 / 字段记忆 / LLM 兜底”各自的贡献。

## 2. 边界与原则（不可突破）

**不做**
- 自动提交、批量海投、定时代投
- 识别/绕过验证码、滑块、风控
- 笔试/在线测评辅助
- 保存或代填网站账号密码
- 读取用户邮箱或短信（通知提取仅限用户手动粘贴文本）

**设计原则**
1. **只填不交**：代码层面拦截对提交/保存/下一步类按钮的程序化点击。
2. **宁可不填，不填错**：低把握字段标黄让用户确认，不静默写入。
3. **写入必须回读校验**：写入后读回页面实际显示值，不一致标红。
4. **本地优先**：档案仅存浏览器本地；无自建服务器。
5. **最小权限**：`activeTab` + 用户点击触发，不申请“读取所有网站”。
6. **LLM 只发必要内容**：兜底时只发字段名和选项，不发个人信息；用到个人经历（开放题）时明确告知发送内容。

## 3. 中国网申的特点（设计依据）

| 系统 | 典型客户 | 对插件的影响 |
|---|---|---|
| 北森 Beisen（含 Phoenix 组件） | 国企、央企、银行、制造业 | 字段多（政治面貌、户籍、家庭成员）、分步骤、自定义下拉、学校联想输入 |
| Moka | 互联网中厂、外企、新消费 | React 单页，受控组件，选项点开才出现在 DOM |
| 飞书招聘 | 字节系及用飞书的公司 | 组件较统一，经历块动态添加；开源项目基本没人做好 |
| 大易 Dayee | 银行、国企、老牌企业 | 偏老式表单，可能有 iframe，字段名不规范 |
| 公司自研 | 腾讯、阿里、华为、美团等 | 每家不同，靠通用识别 + LLM 兜底 |

**共性技术难点**
1. 控件不是原生：Ant Design / Element UI / Arco / TDesign 的下拉、级联（省市区、学校、专业）、年月选择器需模拟点击与搜索。
2. 受控组件：直接改 `value` 页面不认，要用原生 setter 赋值并派发 `input`/`change`/`blur`。
3. 动态多段经历：教育、实习、项目、获奖需先点“添加一条”。
4. 国内特有字段：政治面貌、民族、籍贯、户口所在地、生源地、四六级/计算机等级、GPA 与排名、学生干部、奖学金、是否服从调剂、期望城市、紧急联系人、家庭成员、信息来源、内推码。
5. 同义不同名：“毕业院校/学校名称/就读院校”；选项写法不同（“本科/大学本科/学士”）。
6. 多步表单、iframe、shadow DOM。

## 4. 用户痛点（来自调研）

- 重复填写最耗时（牛客网申助手自述调研：平均每家约 18 分钟，约 76% 为重复信息；厂商数据，未经独立验证）。
- **填错比填不上更危险**：有产品被反馈“信息被清空”“硕士本科填反”“籍贯填不对”。
- 只支持一份简历，用户要按岗位准备多份。
- 开放题仍需手写；小厂自研系统识别不稳。
- 插件只管填，不管投后：不提醒截止、不汇总进度。

## 5. 竞品对照与可借鉴点

主要同类开源项目（星数为调研日页面值）：Job-Application-Helper（62 星）、Autofill-Jobs（36 星，海外 ATS）、EDCYG66/resume-autofill-extension、DDDG637/autoform-filler、Xplore-LAB/qiuzhao-autofill、lxl5211314/job-application-autofill、xiaoxiaobaijiangjun/wangshen-autofill、bzhengak/nw-autofill 等。

**必须吸收的做法**
1. 写入后回读校验，不一致标红。
2. 字段记忆：用户纠正一次，按“label + 控件类型 + 属性”签名记住。
3. 填前出映射表/填后出报告，并说明**每个空白字段的原因**。
4. AI 兜底三件套：只发未匹配字段、输出过本地校验、同站结果缓存。
5. 填不上的字段，聚焦后弹悬浮候选卡，点一下写入。
6. 站点规则优先于通用规则（匹配优先级：站点规则 → 内置别名 → 自定义字段 → 学习记录 → LLM）。
7. 公开覆盖率基线（如 EDCYG66 公布 101/104）。

**共同短板（即机会）**：真实站点验证缺失；北森/飞书/大易支持弱；无人量化 LLM 兜底收益（nw-autofill 自测提升为零）；开放题生成粗糙。

### 6.1 第一版 MVP（目标 3–4 周）：填写 + 投递看板

| # | 功能 | 说明 |
|---|---|---|
| M1 | 个人档案 | 结构化录入，覆盖第 3 节国内特有字段 + 教育/实习/项目/获奖多条经历；`chrome.storage.local`；JSON 导入导出 |
| M2 | 多份档案 | 按岗位方向建多份，一键切换；每次投递记录所用档案 |
| M3 | 一键填充当前页 | popup 触发，识别字段并填入 |

### 6.3 第三版：结合 LLM（DeepSeek API，可兼容 OpenAI 协议）

| # | 功能 | 说明 |
|---|---|---|
| L1 | 简历 PDF 导入档案 | pdf.js 提取文字 → LLM 结构化为固定 schema → 用户预览修改后写入；扫描版另议 |
| L2 | 字段语义兜底 | 规则/记忆都没认出的字段，把字段 label 和选项列表（不含个人信息）发给 LLM，返回需通过本地校验（只能是允许的档案路径或选项原文）；结果按站点缓存 |
| L3 | 开放题草稿 | 结合 JD + 档案生成，严格遵守页面字数限制，给 2–3 个版本，保留最近几版，用户确认后才写入 |
| L4 | 常用回答库 | 写过的好回答入库，相似题复用或改写 |
| L5 | JD 对照 | 提示 JD 关键词与档案经历的匹配/缺口，建议突出哪段经历 |
| L6 | 缺信息暂停询问 | 必填项无依据时停下来问用户，禁止编造 |
| L7 | 通知文本提取 | 用户粘贴笔试/面试通知文本，提取时间与链接，生成日历条目 |

### 6.4 后续（锦上添花）

## 7. 总体架构

**技术栈**：WXT（或 Plasmo）+ Manifest V3 + React + TypeScript；一套代码输出 Chrome 与 Edge 包；测试 Vitest + Playwright。

**模块**
- `popup`：档案切换、一键填充、最近结果
- `side panel`：结果面板、映射表、开放题助手、投递看板
- `content script`：字段扫描、匹配、填充、回读、悬浮卡（页内 UI 使用 Shadow DOM 隔离样式）
- `background (service worker)`：LLM 调用、存储、跨 frame 消息
- `options`：档案编辑、导入导出、API Key 设置

**核心流水线**
```
扫描控件 → 生成字段签名 → Matcher（站点规则→别名→自定义→记忆→LLM） 
→ 置信度分档 → [高风险/低置信度→用户确认] → Filler（按控件类型分派，含 SiteAdapter）
→ 回读校验 → 结果面板（含空白原因）→ 用户检查并自行提交
```

**关键模块**
- `FieldDetector`：多信号提取字段语义（label、aria、placeholder、name/id、分区标题）
- `Matcher`：强/弱别名加权打分，排除规则防误匹配；歧义字段（如单独的“姓名”）无法判断分区时不填
- `Filler`：原生 setter + 事件派发；自定义下拉“点开→读取选项→选择→回读”；日期面板逐级点选；级联逐级选择
- `SiteAdapter`：按域名/页面特征加载 JSON 规则 + 必要的代码适配（北森 Phoenix、Moka 等）
- `Memory`：字段签名 → 用户确认值/档案路径
- `LlmGate`：请求前脱敏检查（确保档案值不外发）、响应本地校验、缓存
- `Safety`：拦截提交类点击，跳过敏感控件

**数据模型（档案）要点**
- 基本信息、求职意向、教育（多条，含 GPA/排名/专业）、实习、项目、获奖、技能/证书（含四六级、计算机等级）、家庭成员、自定义字段。
- 敏感字段（证件号、家庭成员、手机、邮箱）带“允许自动填写”开关，默认关闭或需逐项开启。
- 档案版本：一份“主档案”+ 可派生的岗位方向档案。

**存储**
- 档案/记忆/投递记录/缓存：`chrome.storage.local`（体量大时用 IndexedDB）
- API Key：默认仅会话存储，用户选择后才持久化（明文提示风险）
- 备份导出不含 API Key

## 8. 测试与质量指标（简历数字来源）

1. **真实页面回归集**：保存北森/Moka/飞书/大易及若干自研站点的表单页面快照（脱敏），用于本地回归；另在真实页面做人工冒烟记录。
2. **字段识别准确率**：字段总数、精确命中数、需确认数、未识别数，按系统分别统计并公开。
3. **填写成功率**：回读校验通过率（含下拉、日期、级联分别统计）。
4. **LLM 对照实验**：规则 only vs 规则+记忆 vs 规则+记忆+LLM，报告准确率增量与 LLM 调用次数/Token；缓存命中后的调用下降。
5. **效率**：同一表单手填 vs 插件填+核对的耗时对比（自己实测，说明测试方法，不照搬厂商数字）。
6. **回归脚本**：每次改规则跑全量，防止适配一个站点破坏另一个。

## 9. 隐私与合规

- 数据默认只在本机；无服务器、无统计上报。
- 敏感字段默认不自动填；密码、验证码、银行卡类不识别不保存。
- 调 LLM 前展示将发送的内容类型；字段兜底不含个人值。
- README 声明：只填不交、不绕风控、不抓取网站数据；用户自行对投递内容负责。
- 公开仓库前确认不含真实个人信息、真实页面快照需脱敏；各站点快照仅用于本地测试，注意版权与站点条款。
- 开源协议：MIT；若复制他人 MIT 代码，须保留原版权声明。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 站点改版导致适配失效 | 站点规则 JSON 化、回归集、失败时降级为“标红让用户手填” |
| 选项点开才出现在 DOM | 填充器用“点开→读取→选择→回读”，设超时与重试上限 |
| 范围膨胀 | 严守第 6.5 节暂缓项；第一版只做填写 + 看板 |
| 真实页面样本难拿 | 自己用真实账号逐页保存快照（脱敏），不要求他人账号 |
| 误填造成不良后果 | 高风险字段确认、回读校验、撤销、只填不交 |
| LLM 兜底没提升 | 用实验结果说话；没提升就如实写，并聚焦规则与记忆 |
| 合规/站点条款 | 用户本人触发、本地运行、不绕风控、不批量 |
